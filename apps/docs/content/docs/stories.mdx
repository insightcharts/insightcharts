title: Stories
description: Scrolly keeps one graphic in place and changes its state as the reader scrolls, swipes or steps through a list of text steps.
---

`Scrolly` takes a list of steps and a render function. Each step has its text in `content`, plus any other keys you choose. Those keys hold the state the graphic should be in at that step. Because the same chart instance receives each new state, ECharts morphs between them.

## Scroll mode

The graphic pins while the steps scroll past. Scroll this page slowly. The line chart gains three series, then a highlight, then two annotations, then a shorter time axis.

<StickyDemo name="story-line" props={{ stickyTop: 56, stepHeight: "60vh" }} />

The step crossing the middle of the viewport is the active one. In a container narrower than 768 pixels, like this column, the text cards pass over the graphic instead of sitting beside it. The [stories gallery](/stories) shows the side-by-side layout. The source of this demo:

<DemoSource name="story-line" />

`StoryFrame` in that source is a small wrapper used by the stories on this site. It paints the theme's background behind the story and adds previous and next buttons that scroll to the neighbouring step.

<Callout type="warning" title="Ancestors must not clip overflow">
The pinned graphic uses `position: sticky`, so no ancestor between it and the page may set `overflow: hidden`, `auto` or `scroll`.
</Callout>

## Steps and swipe modes

`mode="steps"` shows one card with previous and next buttons, and needs no scrolling room: use it inside dashboards, slides and cards. `mode="swipe"` turns the steps into cards that swipe horizontally under the graphic. In both, the left and right arrow keys move between steps when focus is inside the story.

<Demo name="story-modes" />

| Mode | Behaviour |
|---|---|
| `"auto"` (default) | `"swipe"` on touch devices in a container under 640 pixels wide, `"scroll"` otherwise. |
| `"scroll"` | Sticky graphic, steps scroll past. |
| `"swipe"` | Horizontal scroll-snapped cards, with previous and next buttons. |
| `"steps"` | One card at a time, buttons only. |

## Writing steps

```tsx
const steps = [
  { id: "all", content: "Hydro generated 11,520 TWh, 53% of the total.", x: "source" },
  { id: "solar", content: "Solar generated 3,870 TWh, 18% of the total.", x: "source", highlight: "Solar" },
  { id: "region", content: "Asia generated 10,590 TWh, 49% of the total.", x: "region", highlight: "Asia" },
];

<Scrolly steps={steps}>
  {({ step, index, progress, count }) => <BarChart x={step.x} highlight={step.highlight} ... />}
</Scrolly>
```

- **Change one thing per step**: the data, the highlight, or the encoding.
- `content` is one or two plain sentences that state what the chart shows at that step, with the number from the data. It follows the same rules as a title; see [writing titles](/docs/highlighting-and-annotations#writing-titles). It accepts any React node.
- `id` is rendered as the step's element id, so `#solar` deep-links to it.
- Return **the same component** from the render function at every step where you want a morph. Swapping to a different component remounts the chart.
- Some changes redraw instead of animating. A treemap that gains or loses its `group` is one. Check each step in the browser and choose a different change when a step does not animate.

The render function receives `step`, `index`, `count` and `progress`, a number from 0 to 1 through the active step. `progress` updates in scroll mode only and is 0 elsewhere.

## Props

| Prop | Default | Purpose |
|---|---|---|
| `steps` | required | The steps. Each needs `content`; other keys are yours. |
| `children` | required | `(state) => ReactNode`, the graphic for the active step. |
| `mode` | `"auto"` | See above. |
| `side` | `"left"` | Which side the text column sits on in scroll mode. |
| `stickyTop` | `0` | Distance from the top of the viewport at which the graphic pins. Set it to the height of a sticky header. |
| `stepHeight` | `"80vh"` | Scroll distance per step, as a CSS length. |
| `index` | uncontrolled | Controlled active step. |
| `onStepChange` | | Called with `(index, step)`. |
| `theme`, `colorMode` | | Same as `theme` and `mode` on charts. |

## Accessibility and fallbacks

All of the step text is in the document. In scroll mode every step is a `<section>` in reading order, so the text can be read with scripting or animation off. Steps mode announces the active card through a polite live region. Charts skip their transitions when the reader prefers reduced motion.
